# 项目收口说明 —— 沿海水域船舶交通流可视分析系统

> 状态：**已收口（2026-10-02）**。本项目不再追加开发，转为 GitHub 归档；本地副本按计划销毁。解冻条件见文末。

---

## 一、一句话结论

本项目作为**「沿海水域交通流可视分析 + 船舶会遇风险感知」工程系统已经完成并可用**；
但作为**「MARL 避碰」科研课题**，经评估**边际价值不足**，故收口、不再追加。

- 原始用途（大创申报）**已不存在**（申报未通过）；
- **CCF 不能支撑**（方向错位：CCF 定位信任增强，本项目属性能侧）；
- 作为工程资产：**已完成，零追加成本保留**。

---

## 二、已交付（可核验）

### 后端（FastAPI + DuckDB/Parquet）
- 分层结构：`backend/app/{core,routers,services}`；数据层 DuckDB + Parquet（弃用 Prisma）。
- 交通流算法（`services/`）：`traffic.py`（航速航向分布 + 行为分类、断面流量、DP 抽稀、主航线提取、OD、时刻快照）、`kde.py`（核密度曲面）、`metrics.py`（12 项指标）、`multivariate.py`（7 轴平行坐标）、`rot.py`（航向角变化率 4 端点）、`cleaning.py`（清洗）。
- **L2 多智能体交互感知层**：`interaction.py`（CPA/TCPA 会遇 + 冲突热点）、`colregs.py`（Rule 13/14/15 局面与责任）、`domain.py`（Fujii/Goodwin 船舶领域 + 船头间距）。
- 主要端点：`/analysis/{density,snapshot,sectional-flow,encounters,conflicts,domain-violations}`、`/analysis/rot/{statistics,by-type,grid,distribution}`。

### 前端（Next.js + TypeScript + deck.gl + zustand）
- WebGL 大数据渲染（Scatterplot/Path/Grid 图层）、联动状态管理、时间回放控制器、7 页签分析面板、区域框选绘制与选区联动。

### 质量底座
- 单元测试 **53 项全绿**（interaction 20 / kde_metrics 14 / rot 9 / traffic 10）；
- 端到端冒烟 **25/25 PASS**；
- 变异验证 **14/14 全部捕获**（`scripts/mutation_check.py`）。

### 数据
- 合成 AIS 数据集：**1,200,001 点 / 1200 船 / 2024-06-01~06-02 / 长江口—舟山海域**（`backend/data`，可用 `scripts/generate_dataset.py` 重建）。

## 四、为什么收口（诚实口径）

1. **原始用途消失**：大创申报未通过。
2. **CCF 不能支撑**：方向错位（信任增强 vs 性能），且时间不够。
3. **作为 MARL 课题边际价值低**：
   - COLREGs 合规避碰 RL 是**极拥挤**领域（2019–2024 上百篇），无新角度；
   - 规划的智能体结构为「本船可训练 + 他船固定轨迹」= **单智能体 RL + 动态障碍**，非真正多智能体协作（CTDE 集中式 critic 退化）；以此为"AeroRider 同构"的类比**不成立**；
   - 数据保真度不达标（见第五节）。
4. **作为工程资产已经完成**：L2 库 + 可视分析系统零追加成本即可保留。

---

## 五、已知局限与诚信披露（留给未来引用者）

- ⚠️ **数据为合成、非实船**；研究水域为**长江口—舟山**（非申报书承诺的罗源湾）。任何引用本项目的"实船验证"表述均不成立。
- ⚠️ **合成数据多船穿模**：6h 窗口 **36 起 <0.05nm 假会遇**（多船独立生成会重叠）。
- ⚠️ **`course` 由带 ~89m 噪声的位置反算**：逐点 ROT **79.9°/min**（约为真值的 23 倍假信号）；默认取 **15min 窗口口径**，绝对值不可当作真实转向率引用。
- ⚠️ **KDE 密度语义**为"累计报文密度"，非瞬时船舶密度。
- L2 交互层为**离线 DuckDB 批处理**，非在线逐步仿真；若要进 RL 环境，复用的是**公式**而非代码。

## 六、最适配方向（核心资产的去向）

本项目**不新开课题**。资产的最适配落点是**回注主线**（LLM 决策 + MARL 执行 + 链上可信）：

1. `colregs.py` / `domain.py` → 作为主线的**「规则约束层」**模块（相对配送域的"无外部规则"，海上域提供**外部法规约束**这一差异化维度）。
2. `frontend/src`（deck.gl + zustand）→ 复用为主线 `Agent×MARL 协商层`等系统的 **demo/可视化前端**。
3. 方法论资产（可复现抽样、噪声判别、变异验证）→ 已沉淀为 skill / memory，跨项目复用。

> 若未来要把海上域做成**真课题**，唯一有科研价值的路径是：**改用美/欧公开 AIS（或经审批的国内卫星/岸基 AIS），把研究设计成"同一框架在三种约束制式下的对比"**（空中=无外部规则 / 海上=外部法规 COLREGs / 链上=信任规则）。那是**重新立项**，不是给本项目补数据。

---

## 七、解冻条件

仅在以下**全部满足**时才考虑重启：
1. 拿到研究区内、密度足以重建单船轨迹的真实 AIS；
2. 明确一个**非拥挤**的研究角度（如上述"三域约束对比"）；
3. 该角度与主线中枢（协商层 / 旗舰）不争抢同一时间段。
