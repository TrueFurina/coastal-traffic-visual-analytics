# 船舶 MARL 避碰扩展规划 —— 三域多智能体协同主线合并方案

> 版本：v1.0（2026-10-02）｜定位：本文件是「船舶轨迹可视分析系统 × 多智能体主线」合并的唯一权威计划源
> 背景：用户核心科研方向为多智能体（MARL/Agent）；AeroRider（无人机-骑手协同配送）与 MARL-ECDSA（可信共识链）已完成机制合并（CCF §6.2 Phase 1）。本规划把船舶项目 L2 交互感知层升级为「决策层」，实现陆-空-海三域多智能体协同叙事闭环。

---

## 一、战略定位：为什么值得合并

### 1.1 现状：船舶项目已具备「感知层」，缺「决策层」

L2 交互层（2026-10-02 完成，44 项测试全绿）已提供避碰所需**全部感知能力**：

| 感知模块 | 能力 | 文件 |
|---|---|---|
| 会遇检测 | CPA/TCPA 判定（1998 起会遇，100% 局面分类） | `services/interaction.py` |
| 规则局面 | COLREGs Rule 13/14/15（对遇/交叉/追越 + 责任判定） | `services/colregs.py` |
| 领域模型 | Fujii 椭圆 4L/1.6L + Goodwin 三扇区（船头间距/横距） | `services/domain.py` |

**缺口**：感知之后没有「决策」——系统能"看见"会遇风险（冲突热点/领域侵犯），但不会"行动"（如何转向/减速）。这正是 MARL 的用武之地。

### 1.2 与主线的三层打通（不是叙事缝合，是机制复用）

```
┌──────────────────────────────────────────────────────────────┐
│        多智能体可信协同主线（陆-空-海 三域闭环）                 │
├──────────────────────────────────────────────────────────────┤
│  决策层（MARL）                                               │
│    AeroRider：无人机+骑手配送   ← MAPPO/CTDE 框架迁移 →  船舶避碰  │
│                                            ↑                  │
│  感知层（环境/观测）                                            │
│    配送订单/路网        ←  复用  →   CPA/TCPA/COLREGs/领域（已就绪）│
│                                            ↑                  │
│  可信层（区块链）                                              │
│    MARL-ECDSA：ECDSA 存证 + SecurityGuard + λ 激励 → 避碰决策上链 │
└──────────────────────────────────────────────────────────────┘
```

| 打通层 | 迁移内容 | 复用产物 |
|---|---|---|
| **框架层** | MAPPO/CTDE 决策循环（train_main.py 架构） | AeroRider `train_main.py` / `MAPPOAgent` |
| **数据层** | 环境观测空间设计 | 船舶项目 L2 三模块输出（会遇/局面/领域特征） |
| **可信层** | 避碰决策存证 + 协作激励 | MARL-ECDSA `trust/`（handoff_ledger + ecdsa_utils + security_guard） |

### 1.3 三域叙事（面试/论文/答辩一页讲清）

> "我构建了一个多智能体可信协同框架，横跨陆-空-海三个配送/航行场景：AeroRider 做无人机-骑手协同即时配送（决策），MARL-ECDSA 做行为可信与激励（信任），船舶项目做沿海水域避碰感知→决策（安全）——三者在同一 MARL 决策循环 + 链上可信机制下统一，是同一技术栈在不同物理域的迁移验证。"

## 二、目标与验收口径

**目标**：在 L2 感知层之上，实现「本船-他船」多智能体避碰决策，训练出可执行的避碰策略（转向/变速），并与可信层打通。

| 验收维度 | 落地标准 |
|---|---|
| 避碰环境 | AIS 场景可加载，本船可行动（航向/航速），他船按真实轨迹运动，CPA/COLREGs/领域特征进观测 |
| MARL 训练 | MAPPO 训练收敛，碰撞率 < 基线（直航/最短时间策略），COLREGs 合规率 ≥ 阈值 |
| 课程学习复用 | AeroRider CL 教训直接应用（预热饱和度/迁移平滑/方差治理） |
| 可信接入 | 避碰关键决策（转向时机/幅度）ECDSA 上链，λ 协作激励接入 |
| 可视化回注 | 避碰决策结果回注可视系统：决策轨迹图层、风险演化时间线 |

## 三、避碰环境设计（S1 核心）

### 3.1 智能体与环境映射

| 要素 | 设计 |
|---|---|
| 智能体 | 本船（自航船，控制自身航向/航速）；他船为环境动态（真实轨迹驱动，非可训练）—— 与 AeroRider「无人机可训练 + 骑手策略固定」异构结构对齐 |
| 动作空间 | 离散联合：航向调整 {大幅左/小幅左/保向/小幅右/大幅右} × 航速 {减速/保速/加速}（15 组合，对应 AeroRider act_dim=8 的可扩展设计） |
| 观测空间 | 目标他船相对方位/距离/CPA/TCPA + 局面类型(COLREGs) + 领域侵犯深度 + 本船航向航速 + 航道边界距离 |
| 奖励 | 碰撞惩罚（CPA<阈值 重罚）+ COLREGs 合规（责任船让路/直航船保向保速）+ 效率（到目的地时间）+ 平稳（转向幅度惩罚）—— 事件驱动（对齐 AeroRider 奖励设计教训：真实安全事件才给信号，防止 reward hacking） |

### 3.2 数据来源

- 训练场景：现有合成 AIS 数据（120 万点）切出会遇窗口（L2 实测 6h 窗口 1998 起会遇，样本充足）
- 验证场景：异常场景（对遇/交叉/追越单独切片、多船会遇、狭窄水道）—— 对齐 AeroRider 静态/动态/异常三数据集设计

## 五、风险与对策

| 风险 | 对策 |
|---|---|
| 合成数据避碰场景失真 | 先切 L2 实测会遇窗口验证环境真实感；导入真实 AIS 后重训（导入管道已就绪） |
| COLREGs 规则与 RL 策略冲突（合规≠最优） | 奖励给合规软约束（非硬编码规则），训练后对照规则基线量化合规率 |
| 多船会遇状态空间爆炸 | 课程学习渐进：单船 → 双船 → 多船；观测只取最近 K 艘他船（对齐配送场景订单数量设计） |
| 10 月 CCF 冲刺冲突 | S1 数据准备可并行（合成切片 + 真实 AIS 下载），主开发严格 11 月起 |
| 与主线代码库分散 | 决策循环收敛到同一仓库（MARL_AeroRider 扩展 maritime 场景），船舶项目保留分析/可视化侧 |
